1 · Qué mandás: el request

client.messages.create(
    model="claude-opus-5-5",
    max_tokens=1024,                     # tope de tokens de la RESPUESTA
    system="Sos un analista de datos.",  # instrucciones generales
    messages=[{"role": "user", "content": "¿Qué planta despachó más m3?"}],
    tools=[...],                         # tools que Claude puede pedir (sección 4)
)
  • system es un parámetro aparte, no un mensaje dentro de messages (docs). En OpenAI va como un mensaje más; acá no.
  • En messages los roles son user y assistant, alternados. No existe un role tool.

2 · La API no se acuerda de nada

“The Messages API is stateless, which means that you always send the full conversational history to the API” (docs). No hay sesión: la memoria es la lista messages que armás vos y reenviás completa en cada llamada.

messages.append({"role": "assistant", "content": r1.content})   # lo que respondió Claude
messages.append({"role": "user", "content": "¿Y cuánto facturó?"})

3 · Qué recibís: la response

{
  "id": "msg_01...",
  "role": "assistant",
  "content": [
    {"type": "text", "text": "Voy a consultar el DWH."},
    {"type": "tool_use", "id": "toolu_01", "name": "query_dwh",
     "input": {"sql": "SELECT planta, SUM(m3) FROM despachos GROUP BY planta"}}
  ],
  "stop_reason": "tool_use",
  "usage": {"input_tokens": 412, "output_tokens": 58}
}
  • content es una lista de bloques tipados (text, tool_use…), no un string ni choices. Una respuesta puede traer texto y un pedido de tool.
  • Texto: "".join(b.text for b in r.content if b.type == "text").
  • stop_reason dice por qué se detuvo la generación. Es lo que usa tu código para decidir el paso siguiente.

4 · El agentic loop

Claude no ejecuta tus tools: te pide que lo hagas y se detiene con stop_reason: "tool_use". Tu código ejecuta, devuelve el resultado y vuelve a llamar, con todo el historial.

messages.create()→ ¿stop_reason?→ tool_use: ejecutar + tool_result↺ end_turn: fin 
while True:
    response = client.messages.create(model=..., tools=tools, messages=messages)
    if response.stop_reason == "tool_use":
        messages.append({"role": "assistant", "content": response.content})
        messages.append({"role": "user", "content": execute_tools(response.content)})
    else:
        return response

Patrón de la doc oficial. En el lab le agregás un tope de iteraciones como red de seguridad.

Valores de stop_reason

ValorQué significaQué hace tu código
end_turnTerminó de forma natural.Usar la respuesta.
tool_usePide ejecutar una o más tools client.Ejecutar, devolver tool_result, seguir.
max_tokensLlegó al tope de max_tokens.Subir el límite o continuar. Un tool_use cortado no se ejecuta: reintentar con más tokens.
pause_turnUn loop de server tools (p. ej. web search) llegó a su tope.Reenviar el contenido assistant para que continúe.
stop_sequenceEmitió una de tus stop_sequences.Leer stop_sequence.
refusalDeclinó responder.Leer stop_details; fallback.
model_context_window_exceededSe llenó la ventana de contexto.Tratar como truncado.

stop_reason llega en respuestas HTTP 200 normales; los errores de la API son 4xx/5xx.

5 · Reglas del tool_result

  1. tool_use_id = id del bloque tool_use que responde.
  2. Va en un mensaje user inmediatamente después del assistant con el tool_use.
  3. Tools en paralelo → todos los resultados en un solo mensaje user.
  4. Los tool_result van primero en el content; texto adicional, después.
  5. Si la tool falla: "is_error": true con un mensaje instructivo, para que Claude se corrija.

Fuente: Handle tool calls.
