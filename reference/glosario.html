Glosario

Términos en inglés, como aparecen en el examen. Se amplía en cada lección.

TérminoDefiniciónLección
Messages APIEndpoint principal para conversar con Claude: recibe system, messages y tools; devuelve un mensaje assistant.0001
statelessLa API no guarda la conversación: cada request lleva el historial completo.0001
system (parámetro)Instrucciones generales; parámetro de primer nivel, no un mensaje de messages.0001
content blockUnidad de content, con un type (text, tool_use, tool_result…).0001
usageConteo de input_tokens y output_tokens de la llamada.0001
agentic loopCiclo request → respuesta → ejecutar tools → devolver resultados, hasta que el modelo termina.0001
stop_reasonCampo de la respuesta que indica por qué se detuvo la generación. Gobierna el control de flujo del loop.0001
tool_use (bloque)Bloque de contenido con id, name e input: el pedido de Claude para ejecutar una tool.0001
tool_resultBloque que devolvés en un mensaje user con el resultado; referencia el tool_use_id.0001
is_errorFlag del tool_result para indicar que la ejecución falló.0001
client toolTool definida y ejecutada por tu aplicación.0001
server toolTool ejecutada por Anthropic (p. ej. web search); puede producir pause_turn.0001
parallel tool useVarios bloques tool_use en una misma respuesta.0001
tool descriptionTexto que explica qué hace una tool, cuándo usarla y sus límites. Principal mecanismo de selección del modelo.0002
tool_choiceParámetro que controla el uso de tools: auto, any, tool (una específica), none.0002
namespacingPrefijos por servicio en los nombres de tools (dwh_…, jira_…) para evitar ambigüedad.0002
retryable errorError que puede resolverse reintentando lo mismo (transitorio). Validación, negocio y permiso no lo son.0002
system promptInstrucciones del parámetro system; lugar natural para el rol (“Sos un revisor de DAX…”).0003
few-shot (multishot) promptingIncluir ejemplos de entrada → salida en el prompt. Guía: 2–4 ejemplos dirigidos a casos ambiguos, con razonamiento.0003
explicit criteriaReglas categóricas de qué reportar y qué omitir; superan a “be conservative” / “high-confidence only”.0003
false positiveHallazgo reportado que no era un problema. Una categoría ruidosa erosiona la confianza en todas.0003
precision / recallPrecisión: cuántos reportes eran reales. Recall: cuántos problemas reales se reportaron.0003
XML tagsDelimitadores (<criterios>, <example>) que separan instrucciones, ejemplos y entrada variable.0003
structured outputsSalida que cumple un JSON Schema. Vía tool (input_schema) o output_config.format; garantizada con constrained decoding.0004
strict tool usestrict: true en una tool: el input cumple el schema siempre.0004
nullable fieldCampo que admite null (["string","null"]) para que el modelo no invente un dato ausente.0004
semantic errorSalida con forma válida pero contenido incorrecto (no suma, campo equivocado). El schema no lo evita.0004
retry-with-error-feedbackReintento que incluye documento, extracción fallida y error específico.0004
Message Batches APIProcesamiento asíncrono: −50%, hasta 24 h, sin SLA, resultados por custom_id.0004
custom_idId por request de un batch para correlacionar resultados (el orden no está garantizado).0004
context windowTodo lo que el modelo puede leer al generar una respuesta (tools, system, messages y la respuesta). Ventana de contexto.0005
context rotDegradación de precisión y recall a medida que crece la cantidad de tokens en la ventana de contexto.0005
lost in the middleEfecto por el que el modelo procesa bien el principio y el final de un input largo y puede omitir lo del medio.0005
case facts blockBloque persistente con datos transaccionales (montos, fechas, ids, expectativas del cliente) que va textual en cada request, fuera del historial resumido.0005
prompt cachingReutilización del prefijo de un request (tools → system → messages) hasta un breakpoint; baja costo y latencia, no la ventana de contexto.0005
cache_controlMarca en un bloque ({"type": "ephemeral"}) que fija el breakpoint del prompt caching; TTL de 5 min por defecto o 1 h.0005
subagentAgente lanzado por otro, con su propia ventana de contexto: recibe solo el prompt que le pasan y devuelve solo su mensaje final.0006
coordinator (orchestrator)Agente que descompone la tarea, delega en subagentes, junta los resultados y decide si volver a delegar.0006
hub-and-spokeArquitectura en la que toda comunicación, errores y ruteo entre subagentes pasan por el coordinador.0006
Task / Agent (tool)Tool con la que un agente lanza un subagente. Task en la guía; renombrada Agent (Task sigue como alias).0006
AgentDefinitionConfiguración de un tipo de subagente en el Agent SDK: description, prompt, tools, model.0006
allowedToolsTools habilitadas para un agente del SDK. El coordinador necesita Task/Agent para delegar.0006
context isolationEl subagente no hereda historial ni memoria del coordinador; el contexto se pasa explícito en el prompt.0006
prompt chainingDescomposición en pasos fijos y secuenciales; para tareas predecibles (review por archivo + integración).0006
dynamic decompositionPlan que genera subtareas según lo que se descubre; para tareas abiertas.0006
attention dilutionPérdida de foco al revisar demasiado material a la vez; se evita partiendo en pasadas locales.0006
MCP (Model Context Protocol)Protocolo para que un programa aparte (servidor) ofrezca tools, resources y prompts a cualquier aplicación compatible.0007
MCP hostLa aplicación de IA (Claude Code, tu agente) que maneja uno o más clients y arma el request a la API.0007
MCP clientComponente del host con una conexión dedicada a un servidor (relación 1:1).0007
MCP serverPrograma que expone primitivas (tools, resources, prompts) a los clients.0007
MCP toolPrimitiva controlada por el modelo: una función que Claude invoca en el loop. Métodos tools/list y tools/call.0007
MCP resourcePrimitiva controlada por la aplicación: contenido de solo lectura con URI (esquemas, catálogos, archivos).0007
MCP promptPrimitiva controlada por el usuario: plantilla que se elige a propósito, p. ej. como slash command.0007
JSON-RPC 2.0Formato de los mensajes entre client y server MCP (métodos con parámetros y resultados).0007
isError (MCP)Flag del resultado de tools/call que marca una falla; el host lo pasa como is_error en el tool_result.0007
