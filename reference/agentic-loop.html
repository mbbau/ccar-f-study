Loop mínimo

messages = [{"role": "user", "content": question}]
for _ in range(MAX_ITERATIONS):                      # guardrail
    r = client.messages.create(model=M, max_tokens=1024, tools=TOOLS, messages=messages)
    if r.stop_reason == "tool_use":
        messages.append({"role": "assistant", "content": r.content})
        messages.append({"role": "user", "content": [
            run_tool(b) for b in r.content if b.type == "tool_use"   # todos en UN mensaje
        ]})
        continue
    return r                                          # end_turn / max_tokens / otros

stop_reason → acción

ValorAcción
end_turnUsar la respuesta.
tool_useEjecutar client tools → tool_result → seguir.
max_tokensSubir límite / continuar. tool_use cortado → reintentar con más tokens.
pause_turnServer tools pausadas → reenviar contenido assistant.
stop_sequenceLeer response.stop_sequence.
refusalLeer stop_details; fallback.
model_context_window_exceededTratar como truncado.

Reglas de tool_result

  • tool_use_id = id del bloque tool_use.
  • Mensaje user inmediatamente después del assistant. Nada en el medio.
  • Paralelo → todos los resultados en un solo mensaje.
  • tool_result primero; texto adicional, después.
  • Error → "is_error": true + mensaje instructivo.
  • Streaming: stop_reason llega en el evento message_delta (es null en message_start).

Trampas

  • Cortar por el texto (“listo”) en vez de por stop_reason.
  • Confundir stop_reason (HTTP 200) con errores de API (4xx/5xx).
  • Olvidar el tope de iteraciones.
