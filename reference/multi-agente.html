Qué es un subagente

  • Otro loop con su propia ventana: system = prompt de su definición · messages = el prompt que le pasa el coordinador.
  • Se lanza con la tool Agent (en la guía, Task). Desde la API es un tool_use más; su mensaje final vuelve como tool_result.
  • No hereda historial ni memoria entre invocaciones. Lo que no está en su prompt no existe.

Prompt del subagente (1.3)

  • Objetivo · formato de salida · tools y fuentes · límites claros.
  • Hallazgos previos completos, con contenido separado de metadata (URL, archivo, página, fecha).
  • Nunca el historial entero “por las dudas”. Coordinador: metas y criterios de calidad, no un paso a paso.

Configuración (1.3)

  • AgentDefinition: description (cuándo usarlo) · prompt (system) · tools (si se omite, hereda todas) · model.
  • Coordinador: allowedTools con "Task" / "Agent".
  • Paralelo: varios tool_use de Agent en una respuesta → un mensaje user con un tool_result por tool_use_id.

Modelos

  • Coordinador capaz + workers baratos. Haiku: volumen, latencia, tareas de subagente. Opus: el punto de partida por defecto.
  • Multi-agente ≈ 15× los tokens de un chat. No sirve si todos necesitan el mismo contexto o dependen mucho entre sí.
