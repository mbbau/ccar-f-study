Ventana de contexto

Ficha rápida. Lección: 0005.

Qué ve Claude

  • Solo el request: tools + system + messages (historial completo, con tool_result). Lo que no está, no existe.
  • Más contexto ≠ mejor: context rot (cae precisión y recall), más costo, más latencia.

Exploración larga (5.4)

  • Síntoma de degradación: respuestas inconsistentes, “typical patterns” en vez de clases concretas.
  • Scratchpad de hallazgos · subagentes para aislar output verboso · resumen entre fases · manifest de estado para retomar · /compact.

Prompt caching (examen: saber que existe)

  • "cache_control": {"type": "ephemeral"} en el último bloque estable. Render: tools → system → messages.
  • Prefix match: un byte distinto invalida todo lo que sigue. Lo estable primero; fechas e ids variables, después.
  • TTL 5 min (se renueva con cada lectura) o "ttl": "1h" · máx. 4 breakpoints · mínimo de tokens según modelo (si no llega, no cachea, sin error).
  • Cambia el precio, no la ventana: el prefijo cacheado sigue ocupando contexto.
