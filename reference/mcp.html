MCP: arquitectura y primitivas

Ficha rápida. Lección: 0007. Se amplía en el Día 08 (transportes, scopes, isError).

Roles

  • Host: la aplicación (Claude Code, tu agente). Arma el request a la Messages API.
  • Client: dentro del host, uno por servidor (1:1). Habla JSON-RPC 2.0 con el servidor.
  • Server: programa que define y ejecuta tools, y ofrece resources y prompts.
  • Claude nunca habla con el servidor: emite tool_use y el client hace tools/call.

Primitivas del servidor

PrimitivaLa controlaMétodosClaude Code
ToolModelotools/list · tools/callmcp__servidor__tool
ResourceAplicaciónresources/list · resources/read · resources/templates/list@servidor:protocolo://ruta
PromptUsuarioprompts/list · prompts/get/mcp__servidor__prompt
  • Catálogos (esquemas, diccionarios, issues, docs) → resource: menos tool calls exploratorias.
  • Acción, o cálculo con argumentos que arma Claude (aunque sea de solo lectura) → tool.
  • Plantilla que elige el usuario (puede tener argumentos) → prompt.
  • Client: elicitation (pedir datos al usuario); sampling y roots, deprecated en la spec 2026-07-28.

Flujo

conexión → tools/list → tools del request → tool_use → tools/call → mensaje user con tool_result (MCP isError → API is_error).

Guía 2.4

  • Servidor de la comunidad para integraciones estándar (Jira); propio, para flujos del equipo.
  • Las tools de todos los servidores se descubren al conectar y están disponibles a la vez.
  • Descriptions detalladas (qué hace, qué devuelve) para que no gane Grep.
